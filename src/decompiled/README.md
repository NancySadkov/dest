# Auto-recovered source tree

This directory is the output of the Ghidra recovery pipeline. It is a complete
decompiler baseline of `STRONG.EXE`, split by the original Borland overlay
segment (i.e. by original source module where the segment name is known).

Start with:

* `MODULES.md` — what each segment/module is, with evidence.
* `MANIFEST.md` — module/function counts and failures.
* `index.tsv` — address, name, size and status of every function.
* `st_types.h` — recovered structs/enums/typedefs.
* `st_globals.[ch]` — recovered global data.
* `st_functions.h` — prototypes for all functions and overlay thunks.
* `st_compat.h` / `st_artifacts.h` — decompiler-output compatibility shims.
* `ovc*.c` — the recovered modules.
* `hard/` — relaxed-limit retries for functions that defeat the default
  decompiler settings (see `hard/README.md`).

The tree is regenerated by `scripts/recover.bat`.

## Status

55 modules, 1021 functions (1020 recovered, 1 pending). The code is decompiler
output, not yet hand-refined. It is intentionally kept close to the original
address/segment layout so it can be compared with the binary and refined
function by function. Known limitations:

* Ghidra's `swi(0x21)` / register-artifact pseudo-variables still need to be
  replaced with real DOS/interrupt helpers.
* `crtl.c` is the decompiled Borland runtime; a rebuild should link TC++ 3.0's
  own `CL.LIB` instead.
* Some global initialisers are still zero-initialised in `st_globals.c`;
  `scripts/ghidra/ExportData.java` recovers the exact values but needs a
  Ghidra-literal-to-C conversion pass.
* Function names are address-based where the original name was not recovered.
* `ovc23:55fe:0000` remains a stub until mzap's `FIXUP_FUNREF` relocation is
  implemented.
* `main.c` and `mouse.c` pass a host `gcc -fsyntax-only` check; most other
  modules expose Ghidra type/field-overlay errors that must be fixed during
  Phase B.

## Compiling

The target is Turbo/Borland C++ 3.0, large model, with `-Y` overlays. The
compatibility header `st_compat.h` maps Ghidra's calling-convention and
integer names onto Borland forms. Compile a module with e.g.:

```
tcc -ml -I. -c ovc02_draw.c
```

### TC30 harness

`scripts/stage_build.py` creates `tmp/buildsrc` with 8.3 filenames and rewrites
the single local include to `st.h`; `src/decompiled/build_tc30.bat` is a
template for a DOSBox/TC30 build. The intended loop is:

```
python scripts/stage_build.py
dosbox-x -conf <a config mounting tmp/buildsrc as C: and tools/TC30 as D:>
```

Current TC30 baseline: 31 of 58 staged modules compile, including the whole
asset-init chain (`ovc44/46/48`), the stash layer (`ovc17/20`), the LBM decoder
(`ovc04`), `main`, `mouse`, and the small helper modules. Remaining modules
still expose decompiler type/overlay artifacts and are the next refinement
target.

`support.c` provides the small helpers used by the rewritten code
(`far_from_u32`, `far_to_u32`, `dw_from_u32`, `dw_to_u32`).

Because the tree still contains decompiler artifacts and the full data image,
linking a working executable is a later phase; see `doc/STATUS.md`.
